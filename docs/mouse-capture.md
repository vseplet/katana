# Захват мыши для игр (mouse capture / pointer-lock)

Контракт между вьювером и хостом для точного управления мышью в играх с обзором
(FPS и т.п.), где приложение захватывает указатель и читает **относительные**
дельты движения. Хостовая часть уже реализована; здесь описано, что должен делать
**вьювер**.

## Зачем

Обычное управление курсором шлёт **абсолютную** позицию (`action:"move/down/up"` с
нормализованными `x,y`) — курсор ставится в точку. Хост инжектит это в абсолютное
uinput-устройство (точное позиционирование десктопного курсора).

Но игры с обзором мышью **захватывают указатель** (pointer-lock) и ждут сырых
дельт `REL_X/REL_Y`. Абсолютное устройство их не даёт → в игре «мышь мёртвая».
Для этого добавлен отдельный путь: сырые относительные дельты → **relative**
uinput-устройство на хосте.

## Переговоры о возможности

В сообщении `hostinfo` хост присылает флаг:

```json
{ "type": "hostinfo", "mouseCapture": true, ... }
```

- `mouseCapture: true` — хост умеет сырой relative-ввод (Linux/uinput). Вьювер
  может показывать/включать режим захвата.
- отсутствует/`false` — режима захвата нет (например, macOS-хост). Не включать.

## Протокол

### 1. Движение в захвате — `action:"rel"`

Пока указатель захвачен, движение мыши шлётся сырыми дельтами (в пикселях), а НЕ
абсолютной позицией:

```json
{ "type": "mouse", "mouse": { "action": "rel", "dx": <int>, "dy": <int> } }
```

- `dx/dy` — сырые дельты за событие. В браузере это `MouseEvent.movementX/movementY`
  (доступны при активном Pointer Lock).
- Хост отдаёт их 1:1 в `REL_X/REL_Y` relative-устройства и **не масштабирует** —
  чувствительность применяет сама игра. (Если нужна доп. чувствительность на
  вьювере — множьте `dx/dy` перед отправкой.)
- Слать по событию `mousemove`; коалесить в кадр (одно сообщение на requestAnimation
  Frame с суммой дельт) — разумно против флуда, но НЕ обязательно.

Отличать от `action:"moverel"` — это ДРУГОЙ путь (десктопный трекпад мобилы,
идёт в абсолютное позиционирование). Для игр использовать именно `"rel"`.

### 2. Сигнал захвата — `type:"capture"`

При входе/выходе из захвата слать:

```json
{ "type": "capture", "on": true }   // указатель захвачен (Pointer Lock получен)
{ "type": "capture", "on": false }  // захват снят (Esc / потеря фокуса)
```

Роутинг движения на хосте **stateless** (по `action`), поэтому потеря этого
сообщения ничего не ломает. Он нужен хосту только для housekeeping:
- пока `on:true` — хост **не шлёт** назад `cursorpos` (кольцо курсора в захвате
  бессмысленно; вьювер и сам должен его скрыть);
- на `on:false` — хост **отпускает все кнопки мыши** (страховка от «залипшей»
  кнопки, если игра держала её в момент выхода).

### 3. Кнопки и колесо — без изменений

Во время захвата кнопки и прокрутка шлются **теми же** сообщениями, что и обычно —
хост доставляет их в игру независимо от режима движения:

```json
{ "type": "mouse",  "mouse": { "action": "press",  "button": "left" } }
{ "type": "mouse",  "mouse": { "action": "release", "button": "left" } }
{ "type": "scroll", "scroll": { "dx": 0, "dy": <int> } }
```

(`press`/`release` не используют координаты — они подходят для режима захвата.
`click`/`dblclick` тоже работают.)

## Рекомендуемая реализация на вьювере (браузер)

1. Показывать кнопку/хоткей «Захват мыши» только если `hostinfo.mouseCapture`.
2. По активации — запросить Pointer Lock на элементе `<video>`:
   `videoEl.requestPointerLock()`.
3. Слушать `pointerlockchange`:
   - захват получен → слать `{type:"capture", on:true}`; на `mousemove` слать
     `{type:"mouse",mouse:{action:"rel", dx:e.movementX, dy:e.movementY}}`;
     скрыть локальный оверлей курсора/кольцо.
   - захват снят → слать `{type:"capture", on:false}`; вернуться к абсолютному
     режиму (`move/down/up`).
4. `Esc` браузер обрабатывает сам (выходит из Pointer Lock) → придёт
   `pointerlockchange` → шлём `capture off`. Предусмотреть свой выход (напр.
   двойной Esc или отдельная кнопка), т.к. первый Esc уходит на снятие захвата, а
   не в игру.
5. Кнопки мыши во время захвата — `mousedown`/`mouseup` → `press`/`release`.
   Колесо — `wheel` → `scroll`.
6. Игры используют относительную модель — забудьте про нормализованные `x,y`, пока
   захват активен.

## Замечания

- Хост создаёт relative-устройство лениво, при первом `action:"rel"`; отдельного
  включения не требуется.
- `cursorpos` от хоста в захвате не приходит — не завязывайте UI-логику захвата на
  его наличие.
- На не-Linux хостах (`mouseCapture:false`) режим не показывать.
